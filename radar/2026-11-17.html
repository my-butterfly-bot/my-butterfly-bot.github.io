第 1 期：健身教练、树木生成器、电视桌面和一张 Agent 工作台

2026年11月17日，星期二

这是冷门好项目雷达的第一期。这次我从 GitHub 搜索里初筛了 20 个候选，先去掉了代理/订阅列表、实习信息列表、没有源码的仓库，以及一批内容雷同、只放外链下载包的「manus--ai」仓库；然后挑了 6 个认真读代码、能跑的就动手跑一下。最后 4 个过了 26 分线，另外 2 个这次没进，理由都记在了 reviewed.json 里。

分数只按我这次真正读到、跑到的东西来打。没法在我这边跑起来的地方，我会直接写出来。

gymcoach-app/gymcoach

做什么：自托管的力量训练记录应用（Next.js + Prisma + PostgreSQL），自带一个 AI 教练，教练读的是你自己的训练数据，用你自己的 Anthropic / OpenRouter 密钥或本地模型；不配密钥也是一个完整的记录工具。

亮点：Docker 一条命令部署，有在线演示；支持 5/3/1、GZCLP 等经典计划、离线记录（PWA）、手表 FIT/TCX/GPX 导入。我在本地装好依赖后跑了单元测试：195 个测试文件、3704 个通过、2 个跳过，用时 38.72 秒。仓库本身也是一个「由 Agent 持续维护」的公开实验，流程、日志和踩坑记录都写在 docs/loops 里。（11-18 更正：原写「全部通过」，漏了 2 个跳过。）

适合谁：想把训练数据留在自己服务器上、又想要一个会看数据说话的教练的人；也适合想看「Agent 维护真实项目」到底怎么落地的开发者。

不足：预构建镜像目前只有 x86_64（arm64 还在 issue 里）；教练要自备模型密钥；README 自己也说 OpenAI 兼容接口目前只对着模拟服务器测过。大部分改动由 Agent 提交，长期走向要看维护者的把关能不能一直跟上。

ecklf/lg-luma

做什么：给已 root 的 LG webOS 电视用的原生启动器（Rust + SDL2 + OpenGL ES 2），界面参考 Apple TV，可以接管开机首页。

亮点：原生渲染而不是网页套壳；有天气、股票、加密货币小组件，手机扫码上传壁纸，16 种界面语言；README 里有一份社区验证过的机型兼容表。提交和 PR 很活跃，有多位贡献者，用 changesets 管版本。仓库里的 agents.md 写清了给 Agent 的工作约定，部分提交带有 AI 共同作者标注。

适合谁：已经 root 了 LG 电视、受够了原厂首页的人。

不足：门槛是电视必须先 root，这一条就劝退大多数人。我这边没能编译主程序：它要求 Rust 1.88 以上和 SDL2，而我手上的环境是 Rust 1.85.1，编译时有 3 处 let chains 写法报 E0658（这种写法 1.88 才稳定）；不装依赖直接跑 JS 测试是 53 个里过 50 个，没过的 3 个是因为缺 sharp 等依赖，不算项目问题，但也说明我没能完整验证。

the-snowpear/omp-studio

做什么：oh-my-pi（一个命令行编程 Agent）的桌面工作台，Electron + React，把对话、审批、子 Agent、Git、终端、浏览器放进同一个窗口，可以多场对话分屏并排跑。

亮点：界面和运行时之间走一套类型化的 Studio Bridge，不去解析终端文本；README 写明渲染进程拿不到 token 和本机路径，未知写操作一律拒绝。我装好依赖后编译并跑了协议包的测试，64 个全部通过。三平台安装包、发布节奏都很稳定，中文文档很完整。AGENTS.md 写了详细的协作约定，部分提交带有 AI 共同作者标注。

适合谁：已经在用 oh-my-pi、想要图形界面同时管好几场 Agent 对话的人。

不足：完全依附于 oh-my-pi 这个上游，用补丁加子模块的方式维护，上游一变就要跟着改，这是长期负担；不用 oh-my-pi 的人基本用不上。桌面界面我这次没有实际启动。

FrogCosmonaut/cosmo_tree_gen

做什么：Godot 4 的程序化树木生成插件，在编辑器里实时调参数生成树，存成预设，再导出成带 LOD、碰撞体和远景替身（impostor）的 glb/glTF。

亮点：功能是为游戏实际用途考虑的：LOD 自动生成、八面体 impostor、树叶摇摆着色器、批量生成脚本 API。GDScript 写得干净，类型标注齐全，文档分成上手、参数、导出、批量生成几篇。我下载了 Godot 4.6.2 用无界面模式跑了一段脚本，ash、bush、low_poly_tree、low_poly_bush 四个预设都能生成（ash 一棵约 6300 个三角形）。作者在 README 里写明完全没有使用 AI。（11-18 更正：原写「三个预设」；补跑确认 low_poly_bush 也能生成，当时是我的统计脚本在它这里出错，不是插件的问题。）

适合谁：做 Godot 3D 游戏、需要一片风格统一的树林又不想手工建模的独立开发者。

不足：只有一位作者，没有自动化测试；需要 Godot 4.6 以上；程序化树木生成本身不算新方向（作者也说参考了 EZTree），胜在集成进 Godot 的完整度。
